# 扣点功能实施计划

## Context（背景）

用户在经营生鲜/农产品业务（使用聚水潭订单系统）。需求：新增侧边栏"扣点"菜单，按商品类别（如蔬菜类）配置扣点百分比（如 7%）。在**批量导入 → 入库**解析"进货单价（采购价）"时，若商品类别命中扣点规则，实际入库成本 = 进货单价 × (1 − 扣点%)，直接以折算后的价格落库，从而影响库存均价（avg_cost）与利润。

扣点语义 = 采购让利：供应商报价的进货单价在扣点后才是用户的真实采购成本。

## 1. 数据模型（backend/app/models.py，文件末尾追加）

```python
class Deduction(Base):
    """扣点规则：按商品类别设置入库扣点百分比。

    批量导入→入库 解析「进货单价」时，若商品类别命中规则，
    实际入库单价 = 原单价 × (1 - percent/100)，直接以折算价作为入库成本。
    """

    __tablename__ = "deductions"

    id: Mapped[int] = mapped_column(Integer, primary_key=True, autoincrement=True)
    category: Mapped[str] = mapped_column(String(64), unique=True, index=True)  # 商品类别，与 Product.category 精确匹配
    percent: Mapped[float] = mapped_column(Float, default=0.0)  # 扣点百分比 0~99.99，如 7 表示 7%
    remark: Mapped[str] = mapped_column(String(255), default="")
    created_at: Mapped[datetime] = mapped_column(DateTime, default=datetime.now)
    updated_at: Mapped[datetime] = mapped_column(DateTime, default=datetime.now, onupdate=datetime.now)
```

- `category` 唯一 → POST 即 upsert。
- 所需类型 models.py 头部均已导入。
- 新表由 main.py lifespan 的 `Base.metadata.create_all` 自动创建，无需 ALTER/migrate。

## 2. 新路由 backend/app/routers/deductions.py（新建）

参照 `pack_rules.py` 模式，`prefix="/api"`，依赖 `get_db` / `get_current_user`：

- `GET /api/deductions`：按类别排序返回全部规则。
- `POST /api/deductions`：按 category upsert（新增/更新 percent、remark）。校验：类别非空；`0 <= percent < 100`，否则 400。
- `DELETE /api/deductions/{did}`：删除规则。

返回结构：`{id, category, percent, remark, created_at, updated_at}`。

## 3. imports.py 扣点应用（backend/app/routers/imports.py）

### 3.1 辅助函数（插在 `class DraftInbound` L334 之前）

```python
def _load_deduction_map(db: Session) -> dict[str, float]:
    """一次性载入全部扣点规则 {商品类别: 扣点百分比}，避免逐行查询。"""
    return {d.category: d.percent for d in db.execute(select(Deduction)).scalars()}


def apply_deduction_price(price: float, product: Product, deduction_map: dict[str, float]) -> float:
    """按商品类别扣点折算单价：原价 × (1 - percent/100)。无规则或 percent<=0 时不折算。"""
    percent = deduction_map.get(product.category) if product and product.category else 0
    if percent and percent > 0:
        return round(float(price) * (1 - percent / 100.0), 4)
    return price
```

同时把 L18 的 `from ..models import ...` 加入 `Deduction`。

### 3.2 parse_inbound_draft（L350-388）

- `detect_header` 之后插入 `deduction_map = _load_deduction_map(db)`（全请求只加载一次）。
- 数量/单价校验**通过之后**、构造 `DraftInbound` 之前：`price = apply_deduction_price(price, product, deduction_map)`。

### 3.3 import_inbounds（L424-464，直接导入端点）

- `detect_header` 之后插入 `deduction_map = _load_deduction_map(db)`。
- 校验通过之后、`create_inbound` 之前：`price = apply_deduction_price(price, product, deduction_map)`（折算价经 `"unit_price": price` 流入 create_inbound → Inbound/StockMovement/FinanceRecord/avg_cost）。

### 3.4 行为约定

- 折算价 `round(..., 4)`，与现有出库派生单价精度一致；金额由 `create_inbound` 的 `round(quantity * unit_price, 2)` 决定。
- 无规则或 percent=0 时价格原样入库。
- `confirm_import_inbounds`（L397-420）直接传预览草稿价，**确认环节不二次折算**（折算只发生在解析时一次）。

## 5. 范围决策

- 扣点**仅作用于批量导入→入库解析**（imports.py 两处）；手工入库（`POST /api/inbounds`）与 AI 录入路径不动——这两处用户显式填写单价，静默打折会造成困惑。
- 聚水潭出库单导入只解析"卖家实收"，无采购价概念，不涉及。

## 6. 验证

1. 启动：项目根 `uv run python dev.py`（后端 :8000 + 前端）；admin1/admin1 登录。
2. 扣点 CRUD：侧边栏"数据工具→扣点"→ 新增「蔬菜 / 7」→ 列表显示；编辑、删除正常。
3. 正向折算：批量导入页下载"入库批量导入模板"，填一行蔬菜类商品（番茄，单价 3.5、数量 10）→ 解析预览单价显示 **3.255**（3.5×0.93）→ 确认入库。
4. 落库核对：入库列表该行 unit_price=3.255、金额 32.55；库存管理 avg_cost 变为 3.255；财务报表采购支出 32.55。
5. 反向验证：未配置类别价格不变；percent 改 0 后不再折算；预览中手动改价后以手改价入库（无双重折算）。
6. 边界：单价负数仍被"数量/单价无效"拦截；percent=100 或负数被 API 400 拒绝；重启后端后 `deductions` 表自动创建。
