# 分仓切换（数据隔离）实施计划

## Context（背景）

用户需要"分仓"管理：不同分仓的商品信息和业务数据**完全隔离**。已确认方案：**每个分仓独立 SQLite 数据库文件**，切换分仓即切换整套数据（商品/库存/订单/财务/备份），现有 `data/erp.db` 归属为「奥斯迪仓」（key=`aosidi`），新分仓从空库开始。侧边栏「设置」分组第一个按钮为「切换分仓」，弹出分仓列表/新建/切换。

## 数据布局

```
data/
  erp.db                    # 奥斯迪仓（不动，key=aosidi）
  warehouses.json           # 注册表 {current, list:[{key,name,db,created_at}]}
  warehouses/{key}.db       # 新分仓（独立库）
  backups/{key}_backup_YYYYMMDD_HHMMSS.db
```

核心原则：`database.py` 是唯一连接点；`get_db()` 依赖在请求创建时按当前仓绑定 session；当前仓为服务端全局状态（进程内缓存 + warehouses.json 持久化 current，重启恢复）。

## 关键文件改动

### 1. backend/app/database.py（核心重构）
- 保留旧符号 `DATA_DIR/DB_PATH/engine/SessionLocal/Base` 指向奥斯迪仓（兼容 keyadmin 与独立脚本）。
- 新增：
  - `WAREHOUSES_FILE`（data/warehouses.json）、`WAREHOUSES_DIR`、`DEFAULT_WAREHOUSE_KEY="aosidi"`
  - `_make_engine(path)`（PRAGMA listener 复用）、`get_engine(key)` 缓存、`warehouse_db_path(key)`（aosidi→erp.db，其他→warehouses/{key}.db）
  - `get_sessionmaker(key)` 缓存
  - `load_warehouses/save_warehouses`（原子写 .tmp+os.replace）、`get_warehouses`、`register_warehouse`
  - `get_current_key()/set_current_key(key)/current_warehouse_name()`（进程内缓存 + 持久化，current 指向不存在的仓时兜底到第一个）
  - `get_db()`：`db = get_sessionmaker(get_current_key())()`（生成器依赖，每次请求绑定当前仓）
  - `get_db_default()`：绑定奥斯迪仓（供 keyadmin 钉死）

### 2. backend/app/initdb.py（新建，从 main.py 抽公共逻辑）
- 把 main.py 的 `migrate()`（L34-98 区域）+ `_backfill_*` + lifespan 里的三个回填循环（default_unit、人工 workload、weight_kg，L281-295 区域）搬入，engine/sessionmaker 参数化。
- `init_warehouse(key, copy_users_from=None)`（幂等）：`create_all` → `migrate`（幂等跳过）→ `seed_units` → `copy_users`（若指定）→ `ensure_seed_users` → 回填（空表自动跳过）。
- `copy_users(src_key, dst_key)`：把源仓 users 全表复制到目标仓（**显式保持 id**，须在 ensure_seed_users 前调用，users 表此刻为空无冲突）。

### 3. backend/app/main.py
- 删除 migrate/_backfill 相关（移入 initdb），lifespan 改为：
  ```
  init_warehouse("aosidi")
  if get_current_key() != "aosidi": init_warehouse(get_current_key())
  # 启动自动备份（针对当前仓） + auto_backup_loop（不变）
  ```
- `from .routers import ... warehouses ...` + `app.include_router(warehouses.router)`。

### 4. backend/app/auth.py
- `make_token(user_id)`：payload 增加 `wh`（当前仓 key，签发时绑定）。
- `verify_token(token)`：校验 `payload.wh == 当前仓`；**旧 token 无 wh 字段视为 aosidi**（兼容存量登录态，切仓后即失效需重登）。
- 调用方零改动（login 自动带上当前仓；get_current_user 默认按当前仓校验）。

### 5. backend/app/routers/auth.py
- `/login` 与 `/me` 返回加 `warehouse: {key, name}`（供前端显示当前仓）。

### 6. backend/app/routers/warehouses.py（新建）
- `GET /api/warehouses`：全员可见，返回 `{current, warehouses:[{key,name,db,is_current}]}`。
- `POST /api/warehouses`：仅 admin。校验名称非空（≤32字）、key 可选自动生成 `whNN`、不重复、文件不存在 → `init_warehouse(key, copy_users_from=当前仓)` → `register_warehouse` → `set_current_key`。
- `POST /api/warehouses/switch {key}`：仅 admin。校验存在 → `set_current_key`（同仓 no-op）。
- 切仓/新建成功后前端会重登（旧 token 失效），端点不返回新 token。

### 7. backend/app/routers/backup.py
- `DB_PATH` 改为 `warehouse_db_path(get_current_key())`。
- 备份文件名：`{key}_backup_{ts}.db`（aosidi 兼容历史 `erp_backup_*` 前缀）；`AUTO_BACKUP_RE` 改为 `^([A-Za-z0-9_-]+)_backup_\d{8}_\d{6}\.db$`。
- `_prune/_list_backups` 只针对**当前仓前缀**的文件；恢复加防呆：文件名必须以当前仓前缀开头，否则 400（防跨仓恢复）。
- keyadmin/main.py L25 改 `from app.database import DATA_DIR, DB_PATH, get_db_default as get_db`（钉死奥斯迪仓）。

### 8. 跨仓配置隔离
- **fresh.py**：`fresh_config_{key}.json`（_load_config/_save_config 按 `get_current_key()` 选文件），防鲜货清单串仓。
- **product_master.py**：json 目录按仓：奥斯迪仓保持 `backend/json/`（兼容现有 5 个文件），新仓用 `backend/json/{key}/`。

### 9. 前端
- **index.html**：侧边栏「设置」分组第一个按钮：
  ```html
  <button class="nav-item" data-action="warehouses"><span class="nav-ico"><svg class="ic"><use href="#i-database"/></svg></span>切换分仓</button>
  ```
  （用 `data-action` 避免 goPage 收 undefined 崩溃）；品牌区下方加 `<div class="warehouse-tag" id="warehouseTag"></div>`。
- **app.js**：
  - nav click 监听：`if (b.dataset.action === "warehouses") { openWarehouseModal(); return; }`；`goPage` 前加 `if (b.dataset.page)` 守卫。
  - `openWarehouseModal()`：复用 `openModal`，列出分仓（当前高亮 + 切换按钮）+ 新建名称输入 + 新建并切换按钮。
  - `loadWarehouses/switchWarehouse/createWarehouse`：调对应 API；成功后先 `POST /api/auth/logout` 再 `location.reload()`（reload 后 /api/auth/me 401 → 停在登录页重登）。
  - `setUser` 填充 `warehouseTag`（"当前分仓：xxx"）。
- **style.css**：`.warehouse-tag` 小字样式。

## 行为约定
- 切换/新建分仓后需**重新登录**（token 绑定仓，安全隔离）。
- 新分仓自动复制当前仓的用户账号（同一套账号、私钥可登录各仓），种子管理员兜底。
- 分仓管理（新建/切换）仅管理员；列表全员可见。
- 自动备份针对当前仓；启动备份针对启动时的当前仓。

## 验证
1. 重启后端 → 登录奥斯迪仓 → 侧边栏「设置→切换分仓」弹窗显示"奥斯迪仓（当前）"。
2. 新建「测试仓」→ 自动切换 → 重登（同一私钥）→ 工作台/库存/订单为空（新库）；切回奥斯迪仓 → 原 300+ 单数据完好。
3. 在测试仓新建商品/入库/出库 → 切回奥斯迪仓确认互不可见。
4. 备份与恢复：奥斯迪仓备份文件名 `aosidi_backup_*`；把测试仓备份恢复到奥斯迪仓应被 400 拦截。
5. 前端 401 流程：切仓后 reload 停在登录页，无报错；侧边栏显示当前仓名。
6. 旧数据完整性：奥斯迪仓商品、9月4号订单、扣点、店铺规则均不受影响。
